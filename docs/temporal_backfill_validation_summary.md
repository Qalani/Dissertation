# Temporal-band backfill — Phase 0 validation summary

Per-sensor validation status for the locally reconstructed 90-day
temporal-persistence bands. Written so it can be pasted into a methods section.

> **This file is regenerated by `Backfill_Temporal_Bands_Local.ipynb` section 7**
> (when `UPDATE_REPO_VALIDATION_SUMMARY` is `True`, the default). The version
> committed here is the pre-run baseline: the S1 status below is already final and
> does not depend on running anything, while the S2 numeric fields are filled in by
> the first Phase 0 run against the real archive. A copy is always written to
> `MyDrive/Winam_Temporal_Backfill/reports/phase0_validation_summary.md`.

---

## Method

The 90-day temporal-persistence bands were reconstructed locally from the source band
already present in every exported snapshot — `NDVI` for Sentinel-2, `VH_corrected` for
Sentinel-1 — with no Earth Engine calls. The lookback window reproduces the export code
exactly: `[end_date − 90 days, end_date)`, inclusive of the start and exclusive of the
end, which because each snapshot's `end_date` is its acquisition date plus one day
**includes the snapshot's own acquisition**. Pixels with fewer than 3 valid observations
in the window are masked and written as the export NoData value (−9999), matching
`updateMask(count.gte(3))` followed by `unmask(-9999)` in the export. The reducer's
delta degrees of freedom is settled empirically in Phase 0 against Earth Engine's own
output rather than assumed.

Sentinel-1 additionally carries `vh_temporal_cv_w90 = std / |mean|`, with the mean and
standard deviation formed over the identical valid-observation set.

## Sentinel-1 — status: **UNVALIDATED**

- Bands reconstructed: `vh_temporal_std_w90`, `vh_temporal_cv_w90` (from `VH_corrected`)

**No validation of the Sentinel-1 bands is possible at present, and none has been
performed.** `EXPORT_S1` is `False` in `Batch_Export.ipynb`, so no Sentinel-1 snapshot
has ever been exported carrying the temporal bands. There is therefore nothing in Drive
to compare the local reconstruction against, and the backfill notebook must not export
one to create a reference.

**The Sentinel-2 result does not transfer to Sentinel-1.** The two sensors differ in
revisit interval, in swath coverage across the AOI, and in the distribution of the
source band, so agreement measured for one says nothing about the other. Sentinel-1
outputs are reported as `UNVALIDATED` in the Phase 0 report, in the run manifest
(carried in the `message` column of every row), and here.

The comparison harness is written to be **sensor-generic**: if `s1_scc_temporal_v1`
files ever appear in the export folder from a separate run, Sentinel-1 validation
happens automatically with no further work, including the two S1-specific comparisons
that are dormant until then — behaviour where the window mean approaches zero (count and
spatial distribution of non-finite or extreme CV values in both versions), and agreement
in per-pixel observation support, which varies far more across the AOI for S1 than S2
because of swath coverage.

## Coverage caveat (both sensors)

Earth Engine reduced over **every scene passing the source-collection filters**,
regardless of coverage. The local reconstruction can only see snapshots that passed the
export coverage gate and reached Drive, and it sees one median-composited observation per
acquisition date where Earth Engine saw each granule separately. Phase 0 section 3b
quantifies the first effect from
`winam_snapshot_validated_predictor_manifest.csv` (the `queued`/`completed` vs
`skipped_low_coverage` split per sensor); section 3c measures the combined effect
directly for whichever sensors have reference exports.

Fewer observations per window means a noisier standard deviation and more pixels falling
below the minimum-observation mask than in the Earth Engine version. This is a property
of reconstructing from exports rather than from source imagery, not a defect in the
estimator.

## Estimator correctness, isolated from coverage

The reconstruction logic was verified end-to-end against a synthetic archive in which
the reference "Earth Engine" band was computed from an identical set of input
observations (`tests/test_temporal_backfill.py` plus a full notebook execution over a
69-snapshot synthetic Drive tree). Under identical inputs the local estimator reproduces
the reference **exactly** — Pearson r = 1.000000, mean bias 0.000000, RMSE 0.000000, zero
masking disagreement — and Phase 0's ddof selection correctly identifies the sample
convention (ddof = 1).

That result isolates the estimator from the coverage difference: it demonstrates the
window semantics, NoData handling, min-obs masking and reducer convention are right, and
says nothing about how much the reduced observation count shifts values on the real
archive. Only the Phase 0 numbers above answer that.

## Known issues preserved deliberately

Earth Engine's behaviour is reproduced exactly even where it is questionable; consistency
with the existing schema matters more than correctness at this stage.

1. **`vh_temporal_cv_w90` is not scale-free.** Its source comment justifies dividing by
   `|mean|` as producing "a positive, scale-free coefficient of variation". That does not
   hold on a dB scale: a multiplicative change in linear backscatter is an *additive*
   shift in dB, which leaves the standard deviation unchanged but moves the mean, so the
   ratio is not invariant. Reproduced as written.
2. **The Sentinel-1 stack mixes orbit geometries.** The source collection filters IW mode
   and VV+VH polarisation but not orbit direction or relative orbit number, so a 90-day
   window mixes ascending and descending passes. The incidence-angle correction
   normalises to 38° but does not address look direction, so the temporal standard
   deviation conflates real change with acquisition geometry. Present in the Earth Engine
   version too.
3. **Sentinel-1 spatial coverage is uneven.** Per-pixel observation counts vary far more
   across the AOI for S1 than S2, so the minimum-observation mask has strong spatial
   structure. A per-pixel observation-count band is retained as an output (Earth Engine
   discards it) so this can be checked directly.

A fourth point is a local policy choice rather than a reproduction: where the S1 window
mean approaches zero, `vh_temporal_cv_w90` is written as NoData rather than ±Inf. Earth
Engine's behaviour there cannot currently be observed. See
`docs/temporal_backfill_integration.md` §7.
